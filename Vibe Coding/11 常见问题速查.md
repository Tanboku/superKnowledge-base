# 11 常见问题速查

> Vibe Coding 高频问题快答，按概念 / 工具 / 技巧 / 项目分组。

## 概念理解

**Q：Vibe Coding 和传统编程的区别？**
从「写代码、背语法」变成「表达需求、迭代验证」。核心能力从实现细节转移到需求表达和验收判断。

**Q：学了 Vibe Coding 还要学传统编程吗？**
不必系统学一门语言，但对技术栈要有基本认知（知道各项技术是什么、能干什么），才能准确表达需求、判断 AI 方案的好坏。

**Q：AI 生成的代码靠谱吗？**
小项目基本靠谱，正经项目必须人工审查：业务逻辑是否正确、错误处理是否完整、有无安全隐患、是否影响其他功能。

**Q：Vibe Coding 会取代程序员吗？**
取代的是「纯翻译式编码」，放大的是需求分析、架构设计、审查验收这些上游能力。会用 AI 的开发者淘汰不会用的。

**Q：MVP 是什么？**
最小可行产品——只做最核心的功能先跑起来，验证后再加东西。见 [[04 五大核心心法]]。

**Q：什么是上下文窗口？**
AI 单轮对话能记住的内容上限，超了旧信息会被挤掉。见 [[10 AI 大模型原理入门]]。

## 工具选择

**Q：Cursor 和 Windsurf 哪个好？**
同类 AI 编辑器，能力在伯仲之间，选一个深入掌握即可，操作逻辑相通。

**Q：免费版够用吗？**
学习阶段够用：各平台免费额度 + 便宜的国产模型 API 能覆盖个人项目。重度使用再考虑订阅。

**Q：零代码平台还是代码编辑器？**
零基础先零代码平台找感觉 → 想自定义代码、做复杂项目再上编辑器（Cursor 起步）→ 熟练后试命令行 Agent（Claude Code）。

**Q：API Key 在哪获取？**
各模型厂商官网（OpenAI、Anthropic、DeepSeek、智谱等）的开发者平台注册申请，注意保管，不要写进代码或提交到仓库。

## 使用技巧

**Q：AI 生成的代码报错怎么办？**
完整复制报错 → 附相关代码和复现步骤 → 说明期望与实际差异。仍不行就换角度描述或开新对话。见 [[07 幻觉与死循环处理]]。

**Q：AI 总用错误的技术栈（比如我明明用 Vue 它写 React）怎么办？**
上下文问题：在规则文件（AGENTS.md）里声明技术栈，每轮对话开头重申，用 @ 引用现有代码作参照。

**Q：怎么让代码符合项目风格？**
提供风格样本：把项目里符合规范的代码贴给 AI 当参考，并把规范写进规则文件。

**Q：代码太冗长 / 重复生成怎么办？**
直接约束：「精简实现，不超过 N 行」「复用已有的 xx 函数」；重复代码让它抽取公共模块。

**Q：代码性能不好怎么办？**
先问 AI 有哪些性能问题和优化空间，让它给方案并说明取舍，确认后再改；改完对比验证。

**Q：怎么处理不安全的代码（如注入、密钥硬编码）？**
让 AI 以安全工程师视角审查；密钥用环境变量；用户输入做校验；关键部分自己复核。

**Q：如何提高提示词质量？**
背景 + 需求 + 约束 + 输出格式四要素，具体而非抽象，复杂任务先拆解。见 [[05 对话工程技巧]]。

## 项目开发

**Q：项目做到一半代码变乱怎么办？**
停下来，回退到最后一个能跑的版本（Git），让 AI 分析现状并给出重构方案，分模块小步重构，别一次性重写。

**Q：怎么部署上线？**
静态/全栈项目：GitHub + Vercel 一键部署；后端服务：云服务器 + Docker。零代码平台自带一键发布。

**Q：上线后出 Bug 怎么办？**
收集报错日志和复现路径 → 本地复现 → 让 AI 修 → 测试通过再上线。保留随时回滚的能力。

**Q：怎么从玩具项目变成真产品？**
补齐工程要素：真实用户调研、数据持久化和备份、错误监控告警、安全加固、迭代节奏。参考 [[08 项目开发流程]]。

**Q：如何测试 AI 生成的代码？**
让 AI 顺手写单元测试并运行；关键路径人工验收；前端用浏览器控制台和设备模拟器检查。

**Q：如何处理多人协作？**
约定同一套规则文件和代码规范进仓库；AI 改动必须经过 review；用分支和 Git 流程管理，AI 代码和人工代码同等对待。

**Q：遇到 AI 解决不了的问题怎么办？**
缩小成最小复现案例；换模型；回退版本；必要时自己读代码——终极 debugger 是你自己。
