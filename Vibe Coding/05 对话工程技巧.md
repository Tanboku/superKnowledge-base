# 05 对话工程技巧

> 提示词工程的升级版：不是写一条完美提示词，而是管理一整轮对话。

## 对话工程 vs 提示词工程

单次提示词只管「这一问」，对话工程管的是多轮协作的全过程：怎么开场、怎么细化、怎么追问纠偏、怎么引导输出。Vibe Coding 的产出质量，八成取决于对话管理能力。

## 迭代式对话五技巧

1. **从大到小，逐步细化**：先定整体（做什么、给谁用），再聊页面，再抠按钮颜色——顺序反了会反复推翻
2. **具体而非抽象**：「界面太丑」→「背景改浅灰、卡片加圆角和阴影、标题字号加大」
3. **提供参考和示例**：给一个想要的文案样例、一张截图、一段喜欢的代码风格，比描述半天管用
4. **分步骤提问**：一次让 AI 做一件事，做完验证再下一件
5. **用提问引导思考**：让 AI 反过来问你（「有哪些信息你需要我补充？」），能暴露你没想到的决策点

## 需求描述框架

一条合格的需求包含四要素：

```text
【背景】我在做一个 XX 项目，技术栈是 XX
【需求】要实现 XX 功能，用户操作流程是……
【约束】不要引入新依赖 / 保持现有风格 / 数据要持久化
【输出】先给我方案不要写代码 / 直接改 xxx.ts 文件
```

## 追问与纠偏

- **追问**：回答太浅就要求展开；一次只追一个点，避免把 AI 带偏
- **纠偏**：结果不对时，说清「期望是什么、实际是什么、差异在哪」，而不是笼统的「不对，重做」
- **要求解释**：「为什么这么实现？有什么风险？」——既帮你学习，也能让 AI 自查漏洞

## 引导输出的三种手段

1. **设定约束**：字数、格式（表格 / 分点）、禁止事项
2. **要多个方案**：「给出 2~3 种实现思路并对比优劣」——把选择题留给自己
3. **角色扮演**：「你作为安全工程师审查这段代码」，切视角能挖出不同问题

## 四大对话陷阱

1. **一次问太多**：多任务混在一条里，AI 容易漏做、乱做
2. **假设 AI 有记忆**：新对话不带上下文就提问，得到的东西和项目对不上
3. **不测试就继续**：错误会层层叠加，最后积重难返；每轮都要验证
4. **过度依赖**：AI 说什么信什么；关键逻辑自己过一遍脑子

## 一个完整的对话节奏

1. 第一轮：给背景 + 目标，只要方案不要代码
2. 第二轮：确认方案后让它实现，指定文件和约束
3. 第三轮：跑起来，带着报错/截图回来修
4. 第四轮：功能 OK 后再做体验优化（动画、边界情况）
