# 09 Harness 与 Loop Engineering

> 从「会用 AI」到「驾驭 AI」：三种 AI 编程模式与两个前沿方法论。

## 三种 AI 编程模式（按项目规模选择）

### Vibe Coding（随性对话）

小项目直接聊，快速出活。适合原型、小工具。缺点：项目一大就失控。

### Agentic Engineering（智能体工程）

中大型项目的思路转变：你不再写代码，而是当**总指挥**——设计系统架构和约束条件，编排 AI Agent 去执行，你负责审查和验收。从「聊天」升级为「有规划地指挥」。

### SDD 规范驱动开发（Spec-Driven Development）

AI 时代的新型方法论：**先把需求写成规范文档，把规范当作代码的唯一真相来源**。

传统流程是边写边改最后补文档（文档和代码必然对不上）；SDD 反过来——规范先行，AI 按规范实现，规范变更走版本管理。代表框架：GitHub 的 Spec Kit、OpenSpec 等。

实际开发可组合：小工具用 Vibe Coding，正经项目用 Agentic 思维，项目越大越需要 SDD 的规范化。

## Harness Engineering（驾驭工程）

Harness 本意是马具：把 AI 想象成一匹马，围绕它搭一整套工作环境和流程，让它跑得又快又稳。**适合企业级项目。**

### 五个核心模块

| 模块 | 解决什么 | 典型手段 |
|------|----------|----------|
| 1. 上下文架构 | 让 AI 了解项目背景和规矩 | 规则文件、文档体系、代码索引 |
| 2. 执行能力 | 给 AI 装上手脚和工具 | 终端执行、MCP、浏览器操作 |
| 3. 任务编排 | 给 AI 安排好工作计划 | 任务拆解、子 Agent 调度 |
| 4. 反馈机制 | 让 AI 自己检查自己 | 自动跑测试、截图验收、循环修正 |
| 5. 架构护栏 | 防止代码越改越乱 | 目录规范、依赖白名单、变更审查 |

前三者决定 AI 的上限，后两者决定项目的下限。

## Loop Engineering（循环工程）

关注 AI 的**自主工作循环**：让 AI 在「执行 → 验证 → 修正」的闭环里连续工作，而不是每一步都等人确认。

典型的自主开发循环：

```
理解任务 → 制定计划 → 写代码 → 运行验证 →
  ├─ 通过 → 提交，进入下一任务
  └─ 失败 → 读报错、定位、修复 → 再验证（循环直到通过或触发止损）
```

### 要点

- 循环的价值在于**把验证从人工搬到自动**：测试、类型检查、截图对比都是循环的燃料
- 必须设置**止损条件**：循环次数上限、失败 N 次即停下问人，防止死循环空烧 token（见 [[07 幻觉与死循环处理]]）
- 循环粒度可分级：小循环（单文件修复）、中循环（单功能开发）、大循环（多任务推进）

## 怎么用起来

个人项目：先把 [[08 项目开发流程]] 的五步跑顺，再逐步引入规则文件和自动验证——这已经是 Harness 的雏形。
团队/企业项目：重点建设护栏（规范、审查、回滚）和反馈（CI 测试、自动验收），让 AI 在围栏内高速跑。
