# 00 Vibe Coding 简介

> 用人话和 AI 聊天，让 AI 生成、修改、优化代码的开发方式。

## 是什么

Vibe Coding = **用自然语言表达意图 + AI 负责实现 + 双方多轮迭代**。

正式一点的说法：以自然语言提示驱动大语言模型（LLM），由 AI 直接生成并迭代代码的「意图驱动开发模式」。

- 你负责想清楚「要做什么」（What）
- AI 负责实现「怎么做」（How）
- 你和 AI 一起迭代优化

传统编程最重要的语言是 Python / JavaScript，Vibe Coding 时代最重要的「编程语言」是母语——把需求讲清楚，就是你的核心编程能力。

## 和传统编程的思维差异

| 维度 | 传统编程 | Vibe Coding |
|------|----------|-------------|
| 核心能力 | 写代码、背语法 | 表达需求、说人话 |
| 学习重点 | 语言、算法、数据结构 | 产品思维、需求表达、迭代优化 |
| 工作方式 | 从零手写 | 和 AI 对话生成 |
| 出问题时 | 自己调试、查文档 | 把错误丢给 AI 修复 |
| 学习曲线 | 陡峭（数月到数年） | 平缓（几天可上手） |

典型流程对比（做天气查询网页）：传统方式要先学语言、学网页、学调 API、学处理 JSON，花几周写代码；Vibe Coding 方式是描述需求 → 看初版效果 → 「加个搜索历史」→ 「改成蓝色调」→ 半小时收工。

## 能做什么

- 网页应用：个人主页、在线工具（待办 / 记账 / 笔记）、博客、官网
- 小程序 / App
- AI 应用：聊天机器人、写作助手、图片工具
- 数据处理：可视化、自动化报表
- 自动化脚本：批量文件处理、爬虫、自动化测试
- 辅助产出：原型图、架构图、演示页面

思路转变：遇到问题先想「能不能让 AI 生成个小工具解决？」

## 三大误区

1. **「用 AI 写代码是作弊」** —— 工具进步不是作弊，就像计算器之于心算、IDE 之于手写。关键是能不能把东西做出来、解决实际问题。
2. **「会让学习能力退化」** —— 恰好相反：AI 生成的代码可以阅读理解、随时追问解释、动手改着玩，在实战中学习比啃书效率高。
3. **「只能做玩具项目」** —— 现在的模型能处理几万行代码的项目、理解复杂业务逻辑、调试疑难 Bug。瓶颈通常不在 AI 能力，而在需求表达和迭代能力。

## 现实局限

- **界面同质化**：AI 生成的页面爱用蓝紫渐变，想要独特设计必须在提示词里明确风格、配色或给参考稿。
- **代码不可控**：项目有体量后，出 Bug 容易陷入「看不懂又舍不得删」的死局。对策：让代码保持简单清晰、每轮生成后都测试、出问题及时回滚。
- **技能退化风险**：有编程基础的人应保持手写能力、理解而非盲用 AI，把 AI 当助手而不是替代品。零基础者反而能在过程中学到编程知识。

## 学习建议

- 先做再学：看完上手教程立刻做一个项目，遇到问题再回头补理论
- 多做项目：从简单到复杂，每个项目做到能用、能看
- 勇于试错：做错了让 AI 修，失败也是经验
- 记录经验：沉淀自己的提示词模板和踩坑笔记
