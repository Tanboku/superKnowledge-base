# 06 上下文管理

> 上下文是 AI 的工作记忆：管理好它，AI 才始终「在状态」。

## 上下文的三个层次

1. **项目级**：技术栈、设计规范、目录结构——相对稳定
2. **功能级**：当前开发的功能是什么、依赖哪些模块——随任务切换
3. **对话级**：本轮对话里的临时信息——最易膨胀和丢失

## 短期记忆：管好上下文窗口

上下文窗口就是 AI 一轮对话能「记住」的内容上限，超了旧信息会被挤掉。

- **一个对话，一个任务**：任务做完就开新对话，别把一整个项目聊成马拉松
- **定期压缩**：对话变长后，让 AI「总结目前的进展、已完成的改动和待办事项」，拿总结去开新对话
- **善用回顾**：继续之前先让 AI 复述「你现在理解的任务是什么」，确认没跑偏再动手

## 长期记忆：把信息沉淀到文件

AI 不记得历史对话，但会读项目里的文件。用文件给它「常驻记忆」：

| 文件 | 作用 |
|------|------|
| `README.md` | 项目身份证：项目是什么、技术栈、目录结构、如何运行 |
| `TODO.md` | 任务清单：已完成 / 进行中 / 待开发 / 已知问题 |
| `AGENTS.md` | 通用 AI 指令文件（优先学这个格式，主流工具都支持）：开发规范、代码风格、测试要求 |
| `CLAUDE.md` / `.cursorrules` | Claude Code / Cursor 各自的规则文件，作用类似 |

要点：文档要**及时更新**——每完成一个功能就更新状态，AI 读到的是最新事实；过时文档比没有文档更害人。

## 上下文断裂：识别与修复

**断裂信号**：AI 开始答非所问、忘记之前约定、重复问过的东西、生成的代码和项目风格脱节。

修复手段（按代价从低到高）：

1. **重新提供上下文**：把关键约定、相关文件再贴一遍
2. **引用之前的内容**：「按我们前面定好的 XX 规范来做」
3. **回到正轨提示词**：明确说「先停一下，目前的需求是 X，请基于我下面给的信息继续」
4. **开新对话**：断裂严重时果断弃聊，带着「进展总结 + 关键文件」重开

## 最佳实践

1. 项目开始时就建好 README / 规则文件，而不是出问题再补
2. 优先用工具的原生上下文机制：`@` 引用文件、规则文件自动加载
3. 保持上下文简洁：贴关键片段而不是整个文件；报错只贴关键几行
4. 层次化组织：项目约定进规则文件，任务进度进 TODO，临时讨论留在对话里
