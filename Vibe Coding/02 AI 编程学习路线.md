# 02 AI 编程学习路线

> AI 编程不只是聊天：从做出东西到做好项目的六个阶段。

核心认知：做简单小工具确实「有手就行」，但项目一复杂，问题就来了——AI 不理解需求、代码质量不稳、改一处坏一处、越做越难维护。所以 AI 编程要学的是一套完整能力。

## 阶段一：AI 编程入门

目标只有一句话：**先把东西做出来**。

- 理解基本概念：Vibe Coding、大语言模型、Token、传统与 AI 编程的思维差异（见 [[00 Vibe Coding 简介]]、[[10 AI 大模型原理入门]]）
- 直接上手零代码平台，跑通「描述需求 → 对话优化 → 验证修复」的循环
- 先做 3~5 个简单项目巩固；零基础不建议一开始就用专业编辑器

## 阶段二：掌握主流 AI 编程工具

零代码平台能力有限，做更复杂的项目需要专业工具。详见 [[03 AI 编程工具与模型选型]]。

- 工具四大类：AI 代码编辑器（Cursor 等）、AI 命令行工具（Claude Code 等）、IDE 插件（Copilot 等）、零代码平台
- 新手建议从 Cursor 起步（可视化界面、编辑审查体验好），熟练后再试命令行 Agent
- 无论选哪个工具，要学的都相通：基本使用（Chat / Agent / 补全 / @ 引用）、核心特性（计划模式、后台 Agent、浏览器测试）、扩展（MCP、Agent Skills）、技巧（多 Agent 并行、子 Agent 拆任务）、自定义配置（规则文件）
- 工具选 1~2 个深入掌握即可，操作逻辑相通

## 阶段三：AI 编程核心技能

把项目做得更好，这些技能不需要编程基础：

| 技能 | 要点 |
|------|------|
| 需求分析 | 先想清楚再动手，大需求拆小任务，小步快跑 |
| 提示词工程 | 角色设定 + 背景信息 + 具体需求 + 约束条件 + 输出格式，见 [[05 对话工程技巧]] |
| 上下文管理 | 规则文件（优先学通用的 `AGENTS.md`）、@ 引用、一个对话一个任务，见 [[06 上下文管理]] |
| Bug 排查 | 说清期望效果 vs 实际效果，附完整报错；AI 卡住就回退版本、换角度描述，见 [[07 幻觉与死循环处理]] |
| Git 版本管理 | AI 时代的「后悔药」：add / commit / push 三件套，diff 看 AI 改了什么，checkout 回退 |
| 开发流程 | 需求拆解 → 方案确认 → 逐任务实现 → 审查 → 重构，见 [[08 项目开发流程]] |
| 部署上线 | 快速部署用 Vercel；进阶学 Docker、云服务器 |
| AI 编程模式 | Agentic Engineering / Harness / SDD，按项目规模选择，见 [[09 Harness 与 Loop Engineering]] |

安全底线：API Key 不写进代码；AI 推荐的第三方包先验证真实存在；用户输入要做校验。企业项目中 AI 代码必须经过人工审查。

## 阶段四：项目实战

分三档递进：

1. **纯前端小工具**：作品集网站、简历生成器、记账、番茄钟、Markdown 编辑器 —— 跑通完整流程
2. **全栈应用**：博客系统、在线商城、社区论坛 —— 前端 + 后端 + 数据库 + 用户认证
3. **AI 应用**：接入大模型 API 做对话、内容生成、知识库；对接支付、对象存储、短信等第三方服务

## 阶段五：进阶提升（按需选学）

- **经验技巧**：对话、质量保障、重构、性能、安全、美化；重点识别系统性失败模式——上下文漂移、功能倒退、架构退化、依赖膨胀
- **上下文工程**：上下文预算设计（哪些常驻、哪些按需加载）、决策日志、窗口管理策略
- **成本管理**：按任务选模型、精简规则文件、合理用工具
- **技术基础**：不必系统学一门语言，但对常见技术栈要有基本认知，才能准确表达需求
- **大模型原理**：Token、上下文窗口、温度、注意力机制——知道 AI 擅长什么才能用好它
- **AI 应用开发技术栈**：LangChain 等框架、RAG、Agent 开发、MCP 服务开发
- **产品思维与变现**：需求分析、盈利模式、SEO / GEO 优化、运营推广

## 阶段六：持续学习

这个领域几个月一变。多关注工具动态、多看别人的作品找灵感、每月至少做一个小项目保持手感；教别人（写博客、答题）是最有效的加深理解方式。

## 时间预期

- 只想快速做出产品：学完阶段一、二即可开工，边做边学
- 系统掌握：约 2~3 个月
- 深入 AI 应用开发 / 求职：再补进阶内容

最重要的永远是**动手做**。
